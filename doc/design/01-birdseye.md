> 一屏内的系统全景。细节一律路由到专题篇（见 [00-index.md](00-index.md)）；本篇随专题篇定稿同步更新。

## 系统闭环

```mermaid
flowchart LR
    subgraph 在线（每轮对话）
        U[用户输入] --> G[langgraph 管道<br/>select→think→检索→组装→生成→落库]
        G -->|人格/记忆检索| C[(Chroma<br/>personality + memories)]
        G -->|读写| P[(PostgreSQL<br/>8 张表)]
        G -.->|可选| W[web 搜索→正文提取→过滤]
        W -->|分片沉淀| C
    end
    subgraph 离线（会话关闭后）
        S[关闭的会话] --> A[归因引擎<br/>transcript→LLM 归因→维度计数]
        A -->|调整/淘汰| P
        A -->|证据/事件回写| C
        A -->|对话分块沉淀| C
        A -->|修剪过期记忆| C
    end
    P -->|激活维度/评分| A
```

**人格 + 记忆 + 自我修正**：在线管道让 Data 稳定扮演角色并沉淀新记忆；离线归因复盘已关闭会话，把成败归因到性格维度、回写证据到人格向量库——角色随对话持续演化。

## 核心机制（各一段话）

- **性格发展**：人格由两层构成——**维度**是性格的结构（哪些性格侧面存在、本轮谁起作用），**素材**是性格的参考内容（示例台词、归因事件与证据，存人格向量库）。在线每轮：LLM 从活跃维度选出本轮起作用的维度（可为空=无人格侧重）注入 think 与 prompt，同时按语义检索 top_k 人格素材进 prompt。离线归因复盘已关闭会话：成败累加维度计数，并把事件摘要、证据片段写回素材层——维度不只被计数，还持续积累支撑自己的素材。长期失败的非核心维度按比率规则淘汰（连带 purge 其素材），核心维度永不淘汰。离线批量运行：手动触发；chat 会话存活期内另由内置 cron 顺带调度——非常驻服务，chat 不开就没有定时、单写者无锁、失败有限重试后转死信。
- **Prompt 分节与预算组装**：每轮的 context 按素材类型分节、各节有优先级，整体在固定 token 预算内贪心填充——装得下的节整段保留，装不下的低优先级节先压缩、再不行让位为省略占位（不空节）；身份设定与参考素材分离承载，素材不占 system 指令位。装不下的老历史不在线压缩摘要，交给记忆检索覆盖。
- **记忆分片入库**：对话记忆由离线归因按 400 字/段切分（句读优先、段间 2 行重叠），web 资料由在线管道按 400 字/片切分；所有 id 由内容哈希稳定派生，重放幂等。
- **召回计数与修剪**：被检索命中的记忆 recall_count+1，达免疫阈值（3 次）的记忆不因超期被删；过期低召回的记忆由离线 run 末尾统一修剪。
- **降级哲学**：LLM 与检索节点的失败一律「保守降级」（原文查询/全保留/空列表/静态兜底文案），绝不穿透到用户；PG 写入事务失败则整轮回滚——对话数据不容静默丢失。

## 重要实现细节（各一段话）

> 非「机制」但改动前必须知道的工程约束与拍板过的折中；细节展开见 00-index 路由的对应专题节。

- **引用即 URL**：web 素材的引用标识就是 metadata.url，LLM 回传的引用必须命中本轮素材清单（known_refs 对账）才被采信。
- **跨库一致性**：PG 事务内不执行 Chroma 写/删；Chroma 副作用在 PG 提交成功后执行、逐条故障隔离。离线是显式「收集+提交后 flush」，在线是「事务块后顺序执行」的弱保证形态——折中方案，如实记录。
