# overview：目标、核心概念与设计原则

> 本节定义 mr.data 的目标、核心概念、设计原则与非目标，是全项目的语义锚点。本文档是 project_object.md 的设计层升级：project_object.md 原文不动，本篇补充改进 1-79 沉淀后的概念扩展，并把每条原则锚定到落实机制与证据。

## 1. 目标

**让 LLM 角色拥有「人格 + 记忆 + 自我修正」的能力。** `[记录·project_object.md]`

三个能力： `[记录·project_object.md]`

1. 稳定扮演一个虚构角色（默认 Data），多轮多会话保持性格一致；
2. 维护长期记忆：性格素材、过往对话（情节记忆）、网络世界知识；
3. 通过离线归因持续优化性格：把会话成败归因到性格维度，强化有效维度、淘汰失败维度。

判断任何改动是否合理的基准：**它服务于这三能力之一，还是支撑机制（可降级、可幂等、可追溯）的健全性。** `[推断]`

## 2. 核心概念

### 2.1 人格（Persona）

角色由固定身份、可演进的性格维度、人格素材共同定义；用户身份（默认 Picard）并入 system prompt。 `[记录·project_object.md, 改进 16/18]`

- **固定身份**：姓名、角色、基础人设，长期不变（PG `fixed_identity`）。
- **性格维度**：描述角色特质的第一人称条目，带成功/失败计数；`core=True` 的核心维度受保护，不被自动淘汰。 `[记录·改进 11/64]`
- **人格素材**：Chroma `personality` 集合中的文档，source_type 三值——`line`（ingest 的示例台词）/`event`（归因产出的人格事件摘要）/`evidence`（归因提取的关键证据片段）。 `[记录·改进 39/61]`
- **用户身份**：对话用户的名称/角色/描述，受保护身份不可删除。 `[记录·改进 18]`

### 2.2 记忆（Memory）

三类记忆 + 人格素材分属两个 Chroma 集合，靠 metadata.source_type 区分。 `[记录·project_object.md, 改进 39]`

- **情节记忆**（`dialogue`）：已关闭会话的完整对话，离线归因后按 400 字/段写入，用于回忆「之前聊过什么」。 `[记录·改进 31/66]`
- **世界知识**（`web`）：在线检索的网页资料按 400 字/片沉淀，用于外部事实。 `[记录·改进 76]`
- **近期上下文**：当前会话最近 N 轮（默认 10 轮）真实消息，每轮从 PG 加载进 DialogueState，不做向量化。 `[记录·改进 27/74]`
- 记忆的存废由召回计数驱动：被检索命中 recall_count+1，达免疫阈值（3）的记忆不因超期被修剪。 `[记录·改进 68]`

### 2.3 在线对话

每轮按「选维度 → think 决策 → 检索 → 组装 → 生成 → 落库」执行，细节见 [online-pipeline.md](online-pipeline.md)。两个概念级机制：

- **think 结构化决策**：一个 LLM 调用同时产出内心独白、人格检索 query、记忆检索 query、是否联网、搜索词——检索 query 由 LLM 改写而非用用户原文，是为语义召回质量。 `[记录·改进 20]`
- **引用即 URL**：web 素材的引用标识就是 metadata.url；LLM 回传的每条引用必须与本轮素材清单对账（known_refs），命不中即丢弃，保证可解释性不为幻觉背书。 `[记录·改进 25/78/79]`

### 2.4 离线归因

对关闭会话复盘：transcript（带内心独白与日志 id）→ LLM 归因 → 维度计数调整 → 证据/事件回写人格向量库 → 对话沉淀为情节记忆。细节见 [offline-attribution.md](offline-attribution.md)。概念级机制：

- **维度选择的下游闭环**：在线每轮实际选中的维度记入 `dialogue_dimension_refs`，离线归因据此区分「本会话激活的维度」与「其余活跃维度」——新维度去重对照用后者。 `[记录·改进 34/51]`
- **淘汰是比率制**：非核心维度总样本 ≥10 且失败比率 >0.33 才停用；终身纯计数会误汰高成功维度。停用无复活路径（停用后不再参与归因，无复活信号源，判为无意义路径）。 `[记录·改进 64]`
- **死信**：单会话归因失败累计 3 次后，未处理日志置为已处理，不再无限重试。 `[记录·改进 67]`

### 2.5 可解释性

回复按内容块（block）组织，每块携带引用列表（id + source_type + 一句话总结）；`source_type` 以检索结果的系统值为准，LLM 填值仅作未命中默认（未命中引用已被丢弃，故实际不进入结果）。 `[记录·改进 25/39, online-pipeline#5]`

### 2.6 沉淀新概念（project_object.md 之后确立的）

这些概念在改进 40-79 中逐渐成为一等公民，后续开发应把它们当既定语义：

- **降级链**：每个 LLM/检索节点的失败都有保守降级方向，总表见 online-pipeline#7。 `[记录·改进 37/55/64/65]`
- **两段式跨库写入**（折中方案）：Chroma 副作用不在 PG 事务内执行；离线为显式「收集+提交后 flush」，在线为「事务块后顺序执行」的弱保证形态。如实记录为折中，见 D-81。 `[记录·改进 61/62, D-81]`
- **稳定 id 幂等**：所有向量写入的 id 由内容哈希稳定派生，已存在则跳过——重放不重复、不重置召回计数。 `[记录·改进 42]`
- **分片对齐嵌入窗口**：所有记忆分片的字符预算（400）≤ 嵌入截断窗口（512 token），启动校验强制。 `[记录·改进 66]`
- **维度选择三态**：`selected_dimension_ids` 区分「空列表=本轮无人格侧重」与「key 缺失=防御回退全量」，避免闲聊轮污染归因。 `[记录·改进 70]`

## 3. 设计原则

project_object.md 的 5 条原则保留原文，此处补充落实机制与证据。

1. **人格结合事实**：回复风格必须符合角色设定，事实作为内容依据。
   落实：prompt guidance 明示「网络资料仅作为回答依据，不要违背你的人格设定」；压缩预算不足时按优先级梯度牺牲——web(40) < memory(60) < personality(70) < identity(90)。 `[记录·改进 48]` `[推断：priority 数值即「人格风格优先、事实其次」的量化，改进 48 修复注水顺序时以「人格优先」为判据]`
2. **结构数据是权威来源**：持久化存储记录真实关系，向量检索只做语义召回。
   落实：维度计数、会话评分、引用快照都在 PG；Chroma 只存可重算的内容与辅助信号（recall_count）。 `[记录·改进 39/43/49]`
3. **会话边界清晰**：活跃会话在线处理，已关闭会话离线复盘。
   落实：离线只处理 `status=closed` 且日志未处理的会话；在线 `_log_dialogue` 只写当前轮。 `[记录·改进 1/33]`
4. **可配置与可降级**：核心功能尽量可开关，模型接口不支持时平滑降级。
   落实：`llm_structured_mode=auto` parse 失败自动降级 schema-in-prompt；web 搜索多 provider 顺序降级；7 个开关型配置（web 搜索/文档过滤/记忆过滤/维度去重等）。 `[记录·改进 22/23/37]`
5. **原型优先**：先验证机制正确性，再考虑规模化和生产级替换。
   落实：pgembed 嵌入式 PG、单实例 Chroma、全表拉回 Python 过滤等简化实现均有意保留。 `[推断]`

补充第 6 条（改进期确立）：

6. **降级不对称**：LLM/检索失败保守降级绝不影响用户；对话数据写入失败不可静默，允许整轮失败。 `[记录·D-80]`

## 4. 非目标

照录 project_object.md 三条：不是通用聊天机器人（重点是角色一致性与性格演化）；不是多智能体系统；不追求生产级高可用。 `[记录·project_object.md]`
